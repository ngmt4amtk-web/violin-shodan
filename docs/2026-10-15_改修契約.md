# 仕事

私（長又）のバイオリン初心者向けWebアプリ「弦しるべ」（~/genshirube-20261014、編集の正本は dist/）を改修してほしい。目的は、課題をやるだけで指の間隔と音程の感覚が身につく構成にすることと、マイクで音程を正しく判定し、高い・低いが一目で分かるようにすること。完成したら下の合格条件を全部満たした状態で止まってほしい。以下は全部私が決めた仕様で、細部の判断は任せる。判断した細部は「返すもの」に理由つきで書くこと。

1. 開放弦のランダム（課題 id=open、リズム「ランダム」）。どの小節も必ず4拍にする。8分音符は必ず2個1組で、整数の拍の頭から1拍を占める。単独の8分音符は出さない。全音符は小節の頭にだけ置き、ランダムの候補に残す。今の `Math.min(b,4-beat%4)` は合計は守るが単独の8分を許しているので直す。

2. アプリ全体を4分の4拍子だけにする。今2拍子なのは 86番（id=eighth34）だけ。下の「8分音符で確かめる」に組み直す。

3. 章立てを次の8章にする（表示は01〜08）。
   - 01 開放弦：はじめての開放弦／7つの弓の高さ／休みの間に次の弦へ／読んで弾く・8つの問題（今の4つのまま）
   - 02 2と3をくっつける：共通メニュー（形 23）
   - 03 はじめての音階：今の課題 scale のまま。スラーだけ消す
   - 04 1と2をくっつける：共通メニュー（形 12）
   - 05 3と4をくっつける：共通メニュー（形 34）。A線では今と同じく「ラ・シ♭・ド・レ・ミ♭」（34low）を選べる。この章の全項目に広げる
   - 06 音階：ハ長調・ト長調（scale12）／1の指から始める音階（scale34）
   - 07 指の形を切り替える：2の指の場所を切り替える（switch2）／4本の弦をつなぐ（connect69）／変わる指と変わらない指（compare。05から移す）／新規「3の指を上げ下げする」（2と3↔3と4。3の指だけ半音動く）／新規「2と3を一緒に動かす」（1と2↔3と4）。新規2つは switch2 と同じ組み立てにする：8小節、前半は形ごとに2小節ずつ、後半は小節の中で形が替わる。弦は4本から選べる
   - 08 楽譜を読んで弾く・応用：読んで弾く・19の問題（reading55）／指の順番を自在に（application94）

4. 共通メニュー。02・04・05は同じ項目を同じ順で持つ。どれも4本の弦から選べ、その章の形で音を作る。
   1. この形をつかむ（今の fingers / fingers12 / fingers34。0から4へ上って戻る）
   2. 指を1本ずつ足す。章の一覧ではこの1行だけにし、押すと「2の指を足す／3の指を足す／4の指を足す」の小さな一覧へ移る。戻ると章の一覧へ帰る。指の順番は今の add2・add3・add4 と同じで、説明文の「半音／全音」はその形に合わせて書き換える
   3. まとめて置いて、下る（今の place）
   4. 指の順番を変えてみる（今の order）
   5. 6組の指を往復する（今の pairs12・pairs34 の順番。02にも置く）
   6. 形を保って続ける（今の keep12。64番の6段の指の順番を、その章の形で弾く。段の選択とランダムは今のまま）
   7. 8分音符で確かめる（86番を4/4に組み直す。1小節目と2小節目は8分音符で 0・1・2・3・4・3・2・1、3小節目は開放弦の2分音符と2分休符）
   8. 新規「開放弦を軸に往復する」。4分音符で 0・1・0・2｜0・3・0・4｜0・4・0・3｜0・2・0・1｜開放弦の全音符
   9. 新規「3音ずつ上り下り」。4分音符で 0・1・2・1｜1・2・3・2｜2・3・4・3｜4・3・2・3｜3・2・1・2｜2・1・0・1｜開放弦の全音符

   教本の原本が別の形の練習（例：1と2の形で2の指を足す）は、指の順番とリズムを原本のまま保ち、音だけその章の形にする。教本に無い組み合わせと新規の課題にはページ番号を出さない（page:null）。今ある課題の id は消さずに使い、保存済みの設定（localStorage `genshirube-v1`）に古い id や今は無い値があっても落ちずに既定へ戻ること。

5. スラーをこの版から全部なくす。scale の slurStart/slurEnd、説明文4つ目のスラーの文、score.mjs のスラー描画（使われなくなるなら消してよい）。

6. カウントダウン。「テンポで通す」は今の4カウントのまま。「1音ずつ」とマイク使用時はカウントなしで、開始するとすぐ最初の音を待つ。再開もカウントなし。マイクをオンにしたら自動で「1音ずつ」に切り替える。

7. 音程の判定を Answer Tuner の「旋律」の目標高さに合わせる。原本は読むだけ：~/AnswerTuner/AnswerTuner/Core/IntonationMath.swift・TonalContext.swift・DrillTarget.swift（drillGetRange、intonationTargets、openStringTargetHz、DrillDifficulty）と、Answer Tuner側のテスト（リポジトリ内を探す）。JSへ移して dist/intonation.mjs に置く。
   - 目標のHzと合格範囲は drillGetRange の context=melodic と同じ計算にする。開放弦は openStringTargetHz と同じ。
   - 合格範囲は Answer Tuner と同じ3段：緩め±15¢・普通±8¢・厳しめ±5¢。既定は普通。
   - 基準は A=442 を既定にし、440 も選べる。どちらも設定として保存する。
   - 調は課題ごとに自動で決める：音階はその調。形の練習は、形と弦が作る音の並びが入る長調（23＝開放弦が主音、12＝開放弦から短3度上が主音、34＝開放弦から完全5度上が主音、34low＝シ♭長調）。切り替えの課題は音ごとに、その小節の形で決める。08の課題は譜面の調号と音から決める。綴りだけで目標が決まり、調が結果を変えないと分かったら、そう報告すること。
   - 今の ±45¢ 判定（app.mjs の 141〜144行付近、engine.mjs の StablePitchGate）は置き換える。

8. 高い・低いの表示。マイク使用中は演奏画面に横向きのメーターを常に出す：中央が正解、左が低い・右が高い、合格範囲を帯で示し、針が今の高さを指す（表示は±50¢で頭打ち）。あわせて「高い」「低い」「ちょうど」の文字と、符号つきのセント値を出す。色だけで伝えない。半音以上ずれて別の音に聞こえる時は「ドに聞こえる・高くして」のように、聞こえた音名と直す向きを出す（音名に音域の呼び名は付けない）。通常文字サイズ・320×568で、今の小節・次の音・拍・停止とメーターが同時に見え、スクロールしないこと。

9. 成功音（マイク使用時だけ）。1音合うたびに短い「ピローン」、課題を最後まで通せたら大きく長い「ピローン」。音の高さは Answer Tuner の成功音（~/AnswerTuner/AnswerTuner/DrillState.swift 213行付近の 880Hz/1320Hz とその理由のコメント）にならう。成功音をマイクが拾っても次の音の判定を通さないこと（鳴っている間と残響の間は判定を止めるなど）。

10. 間違えた時に正しい音を鳴らす（マイク使用時だけ）。参照はふよみ：~/fuyomi/docs/decisions.md の 2026-09-12 の節と ~/fuyomi/js の実装（読むだけ）。音が合格範囲の外で落ち着いたと判定するたびに毎回、その音の正しい高さ（7の目標Hz）を1秒、お手本より大きめの音量で鳴らす。鳴っている間と残響の間は判定を止め、いったん無音になってから判定を再開する。同じ音にとどまり、弾き直せる。高さを探って揺れている間は鳴らさない。

11. 説明文の更新。マイクは音程を判定するようになるので、「マイクは音が出たかを見る補助です。弦の正しさや音程の採点はしません」などの古い説明を今の動きに合わせて直す。見出しやボタンの文言は、たとえを使わず中身をそのまま書く。

12. 仕上げ。sw.js のキャッシュ名を上げ、`node build-portable.mjs` で portable/弦しるべ.html を作り直す。README.md を新しいファイルと検査に合わせて直す。DESIGN.md の末尾に「2026-10-15 改修」の節を足し、採用したことと採らなかった案を理由つきで書く。採らなかった案は次のとおり。響きで確かめる練習（開放弦との同音・オクターブ）と、くっつく2本の連打は今回見送り。合格範囲を入門向けに広げる案（±25/±15/±8）は見送り、Answer Tuner と同じ幅を採用。正しい音を「違う音の時だけ」鳴らす案は見送り、範囲外なら毎回を採用。スラーは次の版へ回す。

## 合格条件（機械判定可能）

1. `node verify.mjs` と `node extension-check.mjs` が exit 0。次の検査を足したうえで通ること。
   - 開放弦のランダムを1000通りの乱数で作り、全小節が4拍・8分音符は2個1組で整数の拍から・全音符は小節の頭だけ
   - 全課題・全弦・全形・全段で拍子が4/4、全小節の合計が4拍
   - 章が01〜08の順で上の構成。02・04・05が同じ9項目を同じ順で持ち、「指を1本ずつ足す」が2・3・4の3つを持つ
   - 全課題でスラーの印が0
   - Answer Tuner 移植の数値が、Answer Tuner側のテストの値と0.1¢以内で一致（「レ長調のVI度は旋律/和声で21.5c分岐する」など、見つかった数値を全部移す）
   - 合格範囲が±15/±8/±5、A=442と440で目標Hzが正しく変わる
   - 誤答→正しい音1秒→判定停止→無音→再開、の順に状態が移る。成功音・正しい音の再生中と残響中に合格も誤答も出ない
   - 「1音ずつ」とマイク使用時はカウントダウンの状態を通らない。「テンポで通す」は4カウントを通る
   - 保存設定に古い id や不正な値を入れても初期化で落ちない
2. `node build-portable.mjs` が exit 0。
3. 画面の検証が通る：`node validation/check-natural-layout.mjs` と `node validation/check-ui.mjs`。新しい章・サブ一覧・メーターの表示を、既存の検査のやり方で足す（マイク入力は偽装でよい）。
4. DESIGN.md に「2026-10-15 改修」の節がある。
