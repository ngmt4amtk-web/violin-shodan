# 仕事

長又の「バイオリン初段」（~/violin-shodan、正本は dist/）と「バイオリン二段」（~/violin-nidan-prototype-20261016、正本は src/、engine.mjs など5ファイルは build.mjs が初段 dist から複写）の、マイク判定まわりを直す。この契約は第1段＝初段側の実装。二段への反映は別契約で行う。

本人の要望（2026-10-20）:
1) 間違えた時などにスピーカーから音が出たあと、マイクが確実に自動で再開する。
2) 弾いても反応しないことがある。しきい値・AudioContext の停止・エコー対策の無視時間を調べて直す。
3) 「音を待っています」と停止表示の切り替わりをスムーズに。
4) マイクが聞いているか止まっているか、いまどの状態かが一目でわかる。
5) 停止表示のまま、音を出しても戻らない状態をなくす。
6) なぜ止まっているのか（正しい音を鳴らしているから、マイクに音が届かないから、など）を示す。
7) 状態が切り替わる時のストレスをなくす。
8) 初段と二段を共通化する（このため状態表示は共有モジュールにする）。

# 根本原因（読解で確認済み。直す対象）

- A. MicJudge の awaitSilence は rms<minRms（高感度0.001、最高感度0.0005）が180ms続くまで戻らず、上限が無い。AGC有効のマイクや弾き続けで永久に「判定停止」のまま残る。success の後も同じ待ちに入るため、次の音をすぐ弾くと止まる。
- B. MicJudge.observe は信頼度不足・無音の1フレームごとに nextNote()（gate.reset）を呼ぶ。StablePitchGate の180ms猶予が死んでいて、320ms連続が成立しにくい。
- C. audio.time は ctx.currentTime。AudioContext が suspended / interrupted になると時間が凍り、判定の期限も tick も止まる。ctx の状態もマイクトラックの ended / mute も監視していない。
- D. 表示が #pitchDirection（「判定停止」）と #micFeedback の二系統で毎フレーム直書き。最小表示時間も遷移も無く、止まっている理由の語も無い。

# 手順

1. engine.mjs（共有）を直す。
   1. 判定の猶予: 聞いている状態で無効フレーム（無音・周波数なし・信頼度不足）が来ても、最後の有効フレームから180ms以内なら gate を消さない。180msを超えたら nextNote()。
   2. success の後: soundEnd + tail が過ぎたら、無音を待たずにすぐ listening に戻る。ただし同じ目標音（±1¢）が続く時だけ、合格後に「切れ目」（無効・無音フレーム、または rms が合格時の50%未満）を1回見るまで gate に数えない。
   3. correction・reference の後: soundEnd + tail の後に awaitSilence に入るが、上限 RESUME_MAX_MS=700ms。早く戻る条件は「静か」が120ms続くこと。静か＝ rms < max(minRms, 0.35 × block 直前の利用者の rms)。上限で戻った時は correction だけ「未装填」にし、success は常に有効。未装填は、切れ目（上の定義）を見るか、ピッチが block 時から30¢以上動くと解除する。
   4. AudioEngine: ctx.onstatechange を onstate コールバックへ通知。state ゲッターと、running でなければ resume() を試す ensureRunning() を足す。
   5. Microphone: トラックの ended / mute / unmute を onhealth コールバックへ通知。health ゲッター（'off'|'live'|'muted'|'ended'）と restart() を足す。既存の audioSession の切替は変えない。
   6. 定数は AUDIO_CUES などの既存の置き場に名前付きで置く（RESUME_MAX_MS、GAP_MS=180、QUIET_MS=120、NO_INPUT_RMS=1e-5、NO_INPUT_MS=2000）。
2. 新しい共有モジュール dist/mic-status.mjs と dist/mic-status.css を作る（二段は build.mjs で複写して使う。アプリ固有の語を入れない）。
   1. 状態キーと表示の表 MIC_VIEW。各キーに tone（live＝聞いている／busy＝一時休止・自動で戻る／stopped＝止まっている・操作が要る／paused＝利用者が止めた）、見出し、理由の文、必要なら操作ボタンの文。
      - starting「マイクを準備しています」
      - listening「聞いています」理由「弾いてください」
      - hearing「聞いています」理由は音程表示に任せる（音はあるが安定したピッチがまだ無い時は「音が揺れています。弓をまっすぐ」程度の短い文）
      - success「合っています」理由「次の音へ進みます」
      - correction「正しい音を鳴らしています」理由「音程が低め／高めで落ち着いたためです。鳴り終わると自動で聞き直します」
      - reference「お手本を鳴らしています」理由「鳴り終わると自動で聞き直します」
      - resuming「まもなく聞き直します」理由「スピーカーの音を拾わないよう待っています。弓を止めるとすぐ戻ります」
      - paused「一時停止中」理由「『再開する』で続きから」／ hidden（画面を離れて止まった時）理由「画面を離れたので止めました。『再開する』で続きから」
      - audioStopped「音の処理が止まっています」理由「通話・他のアプリ・画面ロックなどで止められました。画面をタップすると再開します」操作「再開する」
      - micEnded「マイクが切れました」操作「マイクをつなぎ直す」
      - micMuted「マイクが一時的に使えません」理由「他のアプリが使っている可能性があります。戻ると自動で再開します」
      - noInput「マイクに音が届いていません」理由「マイクの許可や接続を確かめてください」操作「マイクをつなぎ直す」
   2. 純粋なクラス MicStatusModel。毎フレーム { judgeState, cueKind, rms, validPitch, ctxState, micHealth, phase, pausedReason, nowMs, cueStartMs, cueEndMs } を受けて、表示 { key, tone, title, reason, action, progress } を返す。progress は busy の間、自動で聞き直すまでの残りを0〜1で返す（correction・reference・success・resuming で連続して減る1本のバー）。
      - 優先順位: audioStopped > micEnded > micMuted > paused/hidden > starting > correction/reference/success > resuming > noInput > hearing/listening。
      - 深刻度が上がる遷移と、busy→listening/hearing の遷移は即時。listening と hearing の行き来は、新しい側が400ms続いてから変える（ちらつき防止）。その他の遷移は今の表示が300ms以上出てから。
      - noInput は listening 中に rms < NO_INPUT_RMS が NO_INPUT_MS 続いた時だけ。
      - 時刻は ctx の時間でなく performance.now() 系（呼び出し側が渡す nowMs）で判断する。ctx が凍っても表示と復帰は動くこと。
   3. 描画: micPanelHTML() が状態チップ #micStatus（data-tone・data-key、アイコン、見出し、理由、操作ボタン data-action="micRecover"、残りバー）を返し、paintMicStatus(root, view) が変わった所だけ書き換える。既存の #pitchMeter・#pitchNeedle・#pitchDirection・#pitchCents・#micLevel・#micFeedback の id は残す（検査が使う）。チップは aria-live="polite"、見出しの変化だけを読み上げる。
   4. 見た目（mic-status.css）: チップは練習画面のメーターの上に常に1行で見える。tone ごとに色と形の両方で区別する（色だけに頼らない）。live＝緑の点がゆっくり脈打つマイク、busy＝琥珀色の残りバー、stopped＝赤の枠と操作ボタン、paused＝灰色。切替は opacity と背景色の 160ms 遷移。prefers-reduced-motion では脈と遷移を止める。320×568 で既存の「小節・次音・拍・停止・メーター」が同時に見える条件を壊さない。文字200%で切れない。44px ボタン。
3. app.mjs を直す（初段）。
   1. observeMic の muted・feedback の分岐を MicStatusModel に置き換え、チップを描く。#pitchDirection に「判定停止」を出さない（busy・stopped の間はメーターを薄くし、針を隠すだけ）。
   2. 「次の音へ」は鳴らしている間も押せる。押したら鳴っている音を止め（audio.stop()）、通常の進行に入る。「お手本」は音が鳴っている間（soundEnd まで）だけ無効。
   3. tick で毎フレーム監視する: ctx.state が running でなければ audioStopped、1秒に1回まで ensureRunning()。練習中は document の pointerdown・keydown で ensureRunning() と、必要なら mic.restart() を試す（iOS は利用者の操作が要る）。チップの micRecover ボタンも同じ処理。mic.health が ended なら micEnded、muted なら micMuted。visibilitychange で見えるようになったら ensureRunning() を試す（一時停止は解かない）。
   4. 一時停止の理由を区別する（ボタン＝paused、画面を離れた＝hidden）。開始中は #phaseLabel に「マイクを準備しています」（二段の文言に合わせる）。mic.start() が false を返した時は二段と同じく「マイクを開始できませんでした。」でエラーにする。
4. 版と配布: dist/index.html に mic-status.css を読み込む。sw.js のキャッシュ名を上げ（頭は violin-shodan- のまま）、FILES に新しい2ファイルを足す。build-portable.mjs が新しいモジュールとCSSを1ファイルに含めるようにする。validation/app-harness.mjs の読み込み一覧に mic-status を足す。
5. 検査を足す（弱めない）。
   - extension-check.mjs（エンジン・モデル単体）: (a) 有効フレームの間に信頼度不足が1フレーム挟まっても320msで合格する。(b) success の後、大きな rms が続いていても soundEnd+tail で listening。(c) correction の後に同じ外れ音を弾き続けても soundEnd+tail+700ms 以内に listening、その間と後に correction が再発しない、success はできる、30¢動くか切れ目で再装填。(d) correction の後に弓を止めると120msで戻る。(e) 最高感度で rms 0.002 の雑音が10秒続いても、correction 後1.5秒以内に listening（旧来の永久停止の回帰検査）。(f) 同じ目標音が続く時、切れ目なしでは合格しない。(g) MicStatusModel: 優先順位の全組合せ、60ms ごとに有効・無効が入れ替わっても400ms に1回以下しか表示が変わらない、ctx の時間が止まっても nowMs で noInput・audioStopped に入る、busy の progress が単調に減る。
   - verify.mjs（アプリ代役）: ctx.state='suspended' で audioStopped と ensureRunning 呼び出し、マイク ended で micEnded と micRecover による restart、無音2秒で noInput、一時停止と画面離脱の理由の違い、correction 中も「次の音へ」が押せる、#pitchDirection に「判定停止」が出ない。
   - validation/check-ui.mjs（画面、私の側で回す）: 320×568 と 390×844 でチップがメーターと同時に見える、各 tone の見た目、はみ出しなし、文字200%。
6. DESIGN.md に「2026-10-20 マイクの状態と復帰」節を足す（原因A〜D、状態の表、定数、共有モジュール）。README の検査数の記述を実数に合わせる。
